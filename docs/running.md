# Запуск BarkOdd

[← Главная страница](../README.md) · [Полное руководство](guide.md)

## Требования

| Сценарий | Что установить |
|---|---|
| Локальный Go | Go 1.23+, GNU Make 3.81+, Bash 3.2+, OpenSSL. |
| Docker | Docker Engine или Docker Desktop с запущенным daemon, Compose 2.20+, Make, Bash, OpenSSL. |
| Модульные тесты | Go, C toolchain для `-race`, Node.js 20+ и npm. |
| Браузерные тесты | Дополнительно Playwright и Chromium/Chrome; [инструкция](guide.md#проверки-разработки). |

Для первого Go/Docker-запуска нужен интернет, чтобы скачать зависимости или образы. Интерфейс уже встроен в бинарник; npm-сборка для приложения не требуется. На macOS Make и C toolchain доступны в Xcode Command Line Tools; в Windows используйте WSL2.

## Подготовка настроек

```sh
make init
```

Если `.env` отсутствует, команда создаёт его из [`.env.example`](../.env.example), записывает случайный код из 64 шестнадцатеричных символов и устанавливает права `0600`. Существующий файл остаётся без изменений. `make run` и `make docker-up` выполняют эту подготовку автоматически.

```sh
make admin-code
```

Эта команда намеренно выводит код входа в терминал. В обычном запуске код не печатается. Если уже существующий `.env` содержит пустой код, сгенерируйте его через `openssl rand -hex 32` и заполните `ADMIN_CODE` вручную. `make init` не меняет действующие секреты.

Можно держать несколько файлов:

```sh
make init ENV_FILE=.env.local
make init ENV_FILE=.env.production
make run ENV_FILE=.env.local
```

Не добавляйте файлы с секретами в Git. `.env` и `.env.*` исключены из индекса, кроме `.env.example`. Если `ENV_FILE` находится за пределами репозитория или называется иначе, защитите его отдельно.

### Формат и приоритет

Настройки записываются по одной на строку в форме `KEY=value`. Допускаются пустые строки, отдельные строки комментариев `# ...` и значения целиком в одинарных или двойных кавычках. Используйте имена из `.env.example`.

Файл читается как данные: команды, обратные кавычки, `$VAR` и `$(...)` не выполняются и не раскрываются. Комментарии размещайте отдельными строками. Это простой формат литералов, а не shell-скрипт; многострочные значения и shell-подстановки не поддерживаются.

Приоритет: параметры `make KEY=value`, затем экспортированное окружение, затем `ENV_FILE`, затем значения по умолчанию. Для секретов с `$` удобнее файл настроек: сама программа Make имеет собственные правила раскрытия `$` в аргументах.

**Особенность локального запуска:** `make run`, его варианты и `DEPLOY=local` игнорируют `PUBLIC_URL` из файла. Так серверный `.env` с подпутём не ломает локальные Origin/cookie. Для намеренного использования публичного адреса передайте его явно:

```sh
make run PUBLIC_URL=https://camera.example.com
```

Для `DEPLOY=public` и `DEPLOY=macmini` публичные настройки из файла используются. Сам бинарник `.env` не читает — это делает обёртка Make.

## Локальный запуск

```sh
make run        # AUTH_MODE из файла; по умолчанию admin_code
make run-demo   # none: общий кабинет без входа
make run-admin  # admin_code: вход владельца по коду
make run-multi  # multi_user: логины/пароли и отдельный админ
```

Запускайте одну из команд. Адрес — `http://127.0.0.1:8080`, остановка — `Ctrl+C`. Каждый запуск пересобирает `bin/barkodd`, включая изменения в `web/`. Автоматического перезапуска при сохранении исходников нет.

```sh
make run-multi PORT=8090 MEDIA_TRANSPORT=webrtc STUN_URLS=none
```

`PORT` меняет локальный порт; `ADDR` позволяет полностью задать адрес Go-сервера и имеет приоритет над `PORT`. Привязка к внешнему интерфейсу не настраивает HTTPS автоматически. Если нужен HTTPS непосредственно в Go, задайте вместе `TLS_CERT_FILE` и `TLS_KEY_FILE` с доверенным браузером сертификатом.

Для сборки без запуска:

```sh
make build
AUTH_MODE=none DATA_DIR=data/manual ./bin/barkodd
```

## Данные и переключение режимов

| Запуск | Хранилище по умолчанию |
|---|---|
| Go, `none` | `data/local/none/` |
| Go, `admin_code` | `data/local/admin_code/` |
| Go, `multi_user` | `data/local/multi_user/` |
| Docker local | Volume `barkodd_local_<AUTH_MODE>_data` |
| Публичный Compose / Mac mini | Существующий Compose-volume `barkodd_data` с префиксом проекта. |

Разделение по режимам применяется только к локальным конфигурациям. Данные из прежнего `data/` автоматически не переносятся. Чтобы запустить существующее хранилище:

```sh
make run DATA_DIR=./data
```

Не запускайте одновременно два процесса на одном каталоге. Если в хранилище `multi_user` уже появились обычные пользователи, приложение запрещает открыть его в общем режиме. Для экспериментов оставьте раздельные каталоги по умолчанию. Изменение `MEDIA_TRANSPORT` само по себе не меняет хранилище.

`docker-down` не удаляет volumes. Резервная копия должна включать весь каталог данных или весь volume при остановленном приложении. Подробнее — [данные и доступ](guide.md#данные-и-доступ).

## Docker локально

```sh
make docker-up
make docker-ps
make docker-logs
make docker-down
```

Используется [`deploy/compose.local.yaml`](../deploy/compose.local.yaml): один контейнер приложения, порт только на `127.0.0.1`, проверка `/healthz` и отдельное хранилище. Caddy, домен и сертификаты для localhost не требуются. Команда запуска ждёт состояния healthy; это проверяет доступность приложения, а не работу физических камер.

```sh
make docker-up AUTH_MODE=multi_user MEDIA_TRANSPORT=webrtc PORT=8090
```

Порт, режим входа и транспорт можно сохранить в `.env`. Если передавали их аргументами, повторяйте те же значения при следующих командах. Все локальные режимы используют один Compose-проект `barkodd-local`: запуск другого режима заменяет контейнер приложения, его прежний volume сохраняется.

Проверка конфигурации без запуска и без вывода секретов:

```sh
make docker-config
```

## Размещение с HTTPS

### Собственный домен и Caddy

```sh
make init ENV_FILE=.env.production
```

В `.env.production` заполните `APP_HOST` реальным DNS-именем:

```dotenv
APP_HOST=dog.example.com
AUTH_MODE=admin_code
MEDIA_TRANSPORT=websocket
```

Сохраните сгенерированный `ADMIN_CODE`. Укажите DNS-запись на сервер, обеспечьте доступность TCP 80/443 снаружи и освободите эти порты на хосте. Если сервер за роутером, настройте проброс портов. На сервере с репозиторием выполните:

```sh
make docker-config DEPLOY=public ENV_FILE=.env.production
make docker-up DEPLOY=public ENV_FILE=.env.production
make admin-code ENV_FILE=.env.production
```

[`compose.yaml`](../compose.yaml) запускает приложение и Caddy, автоматически получает TLS-сертификат для указанного домена и задаёт приложению `PUBLIC_URL=https://<APP_HOST>`. Проверьте `https://<ваш-домен>/healthz` и откройте сайт на обоих устройствах. Готовность контейнеров не подтверждает правильность внешнего DNS, портов и выдачу сертификата.

Для логов и остановки используйте те же `DEPLOY=public ENV_FILE=.env.production`. Эти команды управляют Docker на текущем хосте; не отправляют исходники на удалённый сервер.

### Существующий Caddy / Mac mini

```sh
make init ENV_FILE=.env.macmini
```

В файле задайте полный адрес, например:

```dotenv
PUBLIC_URL=https://example.com/barkodd/
AUTH_MODE=admin_code
```

Нужны существующая Docker-сеть `web` и Caddy, подключённый к ней. Настройте маршрут:

```caddy
redir /barkodd /barkodd/ 308
handle_path /barkodd/* {
    reverse_proxy barkodd-app:8080
}
```

```sh
make docker-config DEPLOY=macmini ENV_FILE=.env.macmini
make docker-up DEPLOY=macmini ENV_FILE=.env.macmini
```

[`deploy/compose.macmini.example.yaml`](../deploy/compose.macmini.example.yaml) запускает только приложение: alias `barkodd-app`, локальный порт `127.0.0.1:8087`, постоянный volume прежнего проекта `barkodd`. Caddy снимает `/barkodd/` перед передачей запроса. У Go-сервера нет собственного монтирования под подпутём.

Команда не создаёт Caddy и TURN. Не используйте `down -v` или `--remove-orphans` для обновления существующей установки. [Подробности текущей установки Mac mini](guide.md#macmini).

## Если запуск не удался

| Симптом | Что проверить |
|---|---|
| Нет `go`, `make`, `openssl` или Docker | Установите инструмент из таблицы требований; проверьте его наличие в `PATH`. |
| Docker daemon недоступен | Запустите Docker Desktop или службу Docker. |
| `address already in use` | Остановите предыдущий экземпляр или задайте `PORT=8090`; при явном `ADDR` меняйте его. |
| Пустой/неверный `ADMIN_CODE` | Код должен содержать 32–128 символов `A-Z a-z 0-9 _ -`. `make init` не переписывает существующий файл. |
| Конфликт `ADMIN_CODE` и `ROOM_CREATION_KEY` | Уберите прежний псевдоним либо задайте одинаковые значения. |
| Камера не работает по LAN-IP | Откройте приложение через доверенный HTTPS; HTTP подходит только для localhost на том же устройстве. |
| На телефоне не открывается QR | Локальный адрес компьютера не является адресом сервера для телефона; настройте публичный HTTPS. |
| После перезапуска пропал вход | В защищённом режиме войдите повторно и включите наблюдение: сессии не сохраняются на диск. |
| WebRTC не соединяется между сетями | Настройте доступный TURN либо выберите `MEDIA_TRANSPORT=websocket`. |
| JS-тесты требуют новый Node | Выберите установленный Node.js 20+ в `PATH`; приложение само Node.js не использует. |

Справка по поведению Compose: [переменные окружения](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/), [ожидание готовности `up --wait`](https://docs.docker.com/reference/cli/docker/compose/up/).
