# BarkOdd Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. No commits or pushes.

**Goal:** Реализовать self-hosted наблюдение за собакой через браузер с двумя ролями, QR, видео и фотографиями шумовых событий.
**Architecture:** Go HTTP сервер с embedded webUI и атомарным файловым хранилищем. Браузер захватывает медиа и передаёт видео WebRTC; сервер обменивает сигнализацию и хранит события.
**Tech Stack:** Go 1.23, vanilla ES modules/CSS, WebRTC/Web Audio, Go QR encoder, Docker/Caddy/coturn deployment templates.
**Spec:** ../../design.md

## Global Constraints
- Никаких регистраций, нативных телефонных приложений, коммитов или публикации в чужую инфраструктуру.
- Русский интерфейс; frontend работает без CDN и npm build.
- Первая версия источника — ноутбук; capture требует localhost или HTTPS, вкладка должна оставаться открытой.
- Секреты ролей разделены, API и фотографии требуют авторизации. TURN_SHARED_SECRET только на сервере.

## Review Focus
- Зритель не может менять настройки, подделывать события или сигналы хоста — API role tests.
- Краткий шум/долгий лай и фото-cooldown не теряют последнее время — detector + server tests.
- Отозванная ссылка и неизвестные комнаты дают явную ошибку — API + UI checks.
- Пропажа интернета/перезапуск камеры не оставляет ложное live-состояние — browser reconnect check.
- Повреждённое хранилище, опасные размеры запросов и картинки не приводят к потере данных/неограниченному расходу памяти — persistence/validation tests.
