# README и команды запуска

Цель — понятная главная страница Git-репозитория и запуск BarkOdd одной командой после установки Go либо Docker. Пользователь поручил выбрать реализацию; решения ниже приняты исполнителем по существующей структуре проекта.

## Подходы

- Только примеры shell в README оставляют ручную подготовку кода и окружения.
- Только Docker упрощает установку, но мешает существующей разработке на Go.
- Выбран Makefile над существующими Go/Docker-командами: нативный и контейнерный запуск, одинаковые параметры, без изменения приложения.

## Поведение

- `make help` — список команд; `make run` — локальный запуск с авторизацией по коду; `run-demo`, `run-admin`, `run-multi` — явные режимы.
- `MEDIA_TRANSPORT=websocket|webrtc` выбирается независимо от режима входа.
- При первом запуске создаётся приватный `.env` со случайным кодом. Существующие настройки не перезаписываются; код выводится только явной командой `make admin-code`.
- Локальные каталоги и контейнерные volumes разделены по режимам входа. Пользователь может явно указать прежний `DATA_DIR`.
- Docker: локальный app-only запуск, публичный Compose с Caddy, существующий вариант Mac mini за внешним Caddy. Остановка сохраняет данные.
- README содержит быстрый старт, возможности, команды и ссылки. Подробное существующее руководство сохраняется в `docs/guide.md`, инструкции запуска — в `docs/running.md`.

Ограничения: GNU Make 3.81, Bash 3.2, Go 1.23+, Node 20+ только для JS-тестов, Docker Compose с `up --wait`. Секреты не исполняются как shell-код. Публичный HTTPS требует домена/DNS или настроенного прокси; TURN остаётся отдельным сервисом. Коммиты, push и изменения удалённого сервера не входят в работу.

Проверка: реальные локальные старты всех шести сочетаний auth/transport, вход по коду, повторная инициализация, Go/JS-тесты, сборка, Compose config без раскрытия секретов и локальный Docker при доступном daemon.
