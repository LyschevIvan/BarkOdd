# Исправления безопасности BarkOdd

Исправить пять подтверждённых аудитом проблем последовательно, сохранив два транспорта и доступ зрителя по QR. Пользователь поручил выполнить все исправления; выбор реализации — задача исполнителя.

## Подходы

Для доступа к созданию комнат выбран отдельный ключ владельца из окружения. Полноценные аккаунты добавляют ненужную систему пользователей; открытая регистрация с IP-лимитом не предотвращает выдачу TURN посторонним. Пустой ключ закрывает создание, а интерфейс запрашивает ключ только для действия владельца и не сохраняет его. Существующие комнаты и ссылки не удаляются автоматически. Для комнат старой версии требуется явное подтверждение владельцем перед выдачей TURN.

## Поведение

1. `ROOM_CREATION_KEY`: 32–128 URL-safe символа, Authorization Bearer для создания. Не выдавать TURN неподтверждённым старым комнатам; подтверждение требует host token и отдельный ключ владельца.
2. Окончательный отказ host-сессии немедленно освобождает камеру/микрофон и останавливает события. `/events` связывается с текущим активным sessionId; отложенные события завершённого источника отвергаются.
3. Фото проверяются с ограничением частоты/параллелизма комнаты, декодируются вне общего mutex. После декодирования состояние и сессия перепроверяются, прежде чем сохранять событие. Ранее настроенный интервал фотографий сохраняется.
4. Переполнение исходящей очереди камеры сообщениями зрителя отключает виновного зрителя, сохраняя источник и других зрителей. Медленный зритель по-прежнему может отключаться, не мешая источнику.
5. Закрытая регистрация не зависит от общего IP Caddy. Удаление своей комнаты требует host token и явного подтверждения в UI, освобождает слот и отзывает подключения; чужие комнаты удалять нельзя.

## Ограничения

Править текущий каталог: собственного Git-репозитория здесь нет, родительский Git относится к домашнему каталогу. Не выполнять commit/push и не менять рабочий сервер. Исходный снимок хранится вне проекта для проверки diff. Не добавлять библиотеки. Не сохранять секреты в документации, логах или browser storage. Совместимость старого клиента с событиями прекращается ради проверки сессии — после обновления вкладки нужно перезагрузить.

## Проверка

Каждый риск получает регрессионный тест RED→GREEN. В конце — Go race suite, vet, Node suite, браузерный сценарий обоих транспортов на временном хранилище, независимый review изменений.
